# 知识归属与基准

这份文档回答两个问题：**一条知识应该放在哪里**，以及**怎么知道它真的在那里**。

它存在的原因是一条实测教训，不是设计偏好：把原型里 16 个技能专家的混合权重**全部清零**，
三组题的正确率一个都不掉（技能题 56%→56%、事实题 75%→75%、无上下文事实题 8%→8%），
而"不用专家"（56%）比"走路由"（53%）还高 3 个点。也就是说"专家承载领域知识"这件事
在这个 checkpoint 里**根本没有发生**，而在此之前它一直被默认假设着。

结论很直接：**归属不能靠声明，只能靠测。** 所以下面每条规则都配一个能证伪它的测量。

---

## 1. 三个存储位置，各自的能力边界

| 位置 | 物理形态 | 更新代价 | 是否要梯度 | 必须常驻 |
|---|---|---|---|---|
| 常识通路（shared FFN + embedding + 注意力） | 权重 | 全量重训 | 是 | 是（它是显存大头） |
| 技能专家（每层低秩旁路，按整栈加载） | 权重 | 训练/微调 | 是 | 否（可按流量预置，冷栈在 CPU/NVMe） |
| 知识库（外部 SSD + 向量侧车） | 数据 | **2.7 ms/条，零梯度** | 否 | 否 |

实测支撑：热更新 200 条事实后权重指纹逐字节不变、单条 2.7 ms、跨重启仍生效，
新事实准确率 **59% = 把答案手抄进题面的上界**（见 `docs/REPORT.md` 主张6）。

## 2. 归属规则

### R1 会变的一律进知识库
任何可能在两次调用之间改变的事实（端口映射、价格、版本、法条号）都必须进 KB。
进了专家就等于"改一次训一次"。

**怎么证伪**：改一条知识，看是否需要梯度。当前答案是不需要（2.7 ms、零梯度、跨重启生效）✓

### R2 能靠"取到"解决的进 KB，需要组合/变换/风格的进专家
判据是**上界探针**：把答案原文写进题面就能答对 → 缺的只是"取到"，属 KB；
写进去也不会（要多步变换、格式转换、风格判断）→ 属专家。

**怎么证伪**：`presentation_gap = 上界 − 检索开`。这个数曾经 = 11pp，全部来自检索片段的
呈现格式（缺 `【已知】` 前缀 + 注入了第二条干扰项），修完归零 ✓——它证明那批知识是纯取到型。

### R3 归属必须可测，每次训练后自动跑
`python tools/attrib.py --work <目录>` 输出四个 gap 和判定。
**若 `gap_experts ≤ 0`，本次训练没有产生任何专家知识**，此后任何关于动态 MoE
（驻留、数量、路由质量）的结论都不成立、不得引用。

**怎么证伪**：探针本身就是证伪器。它已经证伪过一次（见开头）。

### R4 一条知识只能有一个权威来源
同时进 KB 和权重 = 更新时必然不一致：改了 KB，模型还是按权重答。
curator 写入时若模型"不用检索也答对"，要么改写 KB，要么触发 L2，不能并存。

**怎么证伪**：`facts_conflicting_with_kb` 计数（探针第 4 项）。> 0 就必须先消歧。

### R5 参数性知识（L2）是例外，必须记账
哪些知识被沉淀进了专家权重要有清单。**R1 那类"会变的"知识禁止走 L2**——否则它一改就失效，
而失效是静默的。

**怎么证伪**：L2 之后重跑 R1 的探针；若该条知识已不可热更新，就是走错了层。

### R6 常识通路只放语言能力，不放事实
共享通路一旦把事实背下来，专家就永远不会被用到（这正是当前状态）。

**怎么证伪**：把共享通路容量砍窄（原型已把 `reasoner_hidden` 压到 64）再看准确率是否下降。
**注意这条现在还没通过**：容量压到 64、专家全部清零，准确率都不变——说明事实既没进共享通路
也没进专家，而是进了 **tied embedding + 注意力**（词表只有 512，答案是语料里逐字出现的短串）。
所以 R6 的真正约束对象是 embedding，不是 FFN。见 B2。

### R7 已验证的知识必须压过模型先验，而且这要单独测
知识库是权威来源——这是"哪里不对修哪里"的前提。但模型对同一个问题有自己的先验答案，
实测过它会**压过检索到的证据**：留出端口里有 20 条模型不给检索也能答，答的是一个存在但错误
的服务名；给它看正确的 KB 片段后，仍有相当比例不改口（见 `tools/attrib.py` 的
`evidence_reliance`）。这条不测，就会把"先验压过证据"误诊成"检索没做好"。

**怎么证伪**：探针第 5 项 `evidence_reliance`（先验答错时是否改口采纳 KB 值）与
`evidence_makes_it_worse`（先验本来对、注入检索反而答错）。前者要接近 1，后者要接近 0。

**实测（work-scaled）**：`evidence_reliance = 73%`（先验答错 22 条，只有 16 条改口采纳 KB），
`evidence_makes_it_worse = 0`。同时"把答案手抄进题面"的上界也只有 75%，和检索开完全相同。
这三条合起来定位了所有准确率上限的位置：**检索（命中 100%）和呈现（gap 0）都不是瓶颈，
瓶颈是模型不肯照抄给它的证据**。训练侧的对应做法是冲突改写训练（`KSR_CONFLICT`）：训练事实题时
按一定比例把上下文里的服务名换成错的、目标也跟着换，让模型学"【已知】写什么就答什么"。
评测时上下文都是对的，所以这条规则只会帮忙不会添乱（副作用实测为 0）。

**冲突改写训练实测有效**（`KSR_CONFLICT=0.5`，其余配置与步数完全不变，`work-conflict`）：

| 测什么 | 修之前 | 之后 |
|---|---|---|
| 主张2 留出端口，检索开 | 75% | **92%**（检索命中率仍 100%，抄写成功率 92%） |
| 主张6 新事实（答案只能检索到） | 59% | **89%** |
| 上界（答案手抄进题面） | 75% | 89%（与检索开相等 ⇒ 检索侧确实没有剩余问题） |
| **证据优先率 `evidence_reliance`** | 73% | **91%**（先验答错 23 条，改口 21 条） |
| `evidence_makes_it_worse` | 0 | 0 ✓ |
| 主张4 复犯率 / 主张5 参数沉淀 | 0 / 未答对 | 0 ✓ / 答对 ✓ |

91% 还没到 B8 的 95% 线，剩下 2 条是完全不改口的。另外 `PRIOR_CONFLICTS_WITH_KB` 仍是 21 条：
模型对没见过的端口照样会自信地猜一个存在但错误的服务名——认账训练把它压住了，
但"没有证据时应该拒答"这件事还没有实现（见 R4）。

这是本项目第二个有硬证据的架构主张：**知识外置不只是"能取到"，而是"取到之后模型会认账"**——
而"认账"是训练出来的，不是检索出来的。

## 3. 基准

| 编号 | 测什么 | 怎么测 | 通过线 | 当前状态 |
|---|---|---|---|---|
| **B1 知识承载** | 知识到底在哪 | `tools/attrib.py` | `gap_experts > 0` **且** `gap_kb > 0` | ✗ 两个配置上专家清零都是 **0 题变化**；知识要么在注意力（43.8%）要么在常识 FFN（关掉只剩 3.1%），都在必须常驻的部分。`gap_kb = +88pp` ✓ |
| **B2 规模必要性** | 共享通路背不下时的规模 | 每领域映射数 N 扫描（`KSR_INTENTS`），测 gap 随 N 的变化 | 同一 N 下 `gap_experts` 明显 > 0（带置信区间） | 进行中，方法学的两个坑已填掉（见下） |
| **B3 热更新零重训** | 更新 KB 是否需要重训 | 主张6：插入 N 条 → 指纹 / 新事实 vs 上界 / 旧题 / 跨重启 | 指纹不变、新事实 = 上界、旧题不受影响 | ✓ 89% = 上界（修 R7 前 59%） |
| **B4 检索随规模不退化** | 库变大后召回是否掉 | `tests/test_kb_retrieval.py`：2000 条库 + 池子压到 32 | 召回 100%，且与库规模无关 | ✓ 286/286（修前 5/286） |
| **B5 硬件门槛** | 到底需要什么硬件 | `tools/ksr_calc.py` 解析 + `tools/bench.py --device/--hot-experts` 实测 | 报**常驻字节 / 每 token 读写字节 / 峰值驻留 / 冷专家首调延迟**，不报参数量 | 口径已建；实测在 180M 上是负的（见下） |
| **B6 自我纠错** | 会不会反复踩同一个坑 | 主张4：写错 → 回写 → 审核 → 复测 | 复犯率 = 0；补测拒答率 | ✓ 复犯率 0→0；拒答率未测 |
| **B7 效率对照** | 同参数量下是否更省 | 同参数稠密基线，GPU + batch 扫描 | 比值 > 1 且可复现 | ✗ 修完分发仍是 0.70–0.99× |
| **B8 证据优先** | 取到的知识模型认不认 | `tools/attrib.py` 的 `evidence_reliance` / `evidence_makes_it_worse` | 前者 ≥95%，后者 = 0 | 73% → **91%**（`KSR_CONFLICT=0.5`），副作用 0 ✓，未到 95% 线 |

### B2 的实测记录（三个坑，每一个都会让结论变成假阳性或假阴性）

| 做法 | 结果 | 判定 |
|---|---|---|
| 扩映射数、答案也加编号后缀 | N=40 词表 1469、N=160 词表 3389，准确率塌到 6% / 3%，gap 恒 0 | **错**：tied embedding 属于共享通路，加映射的同时给被考对象扩容，测不出"背不下" |
| 答案只从原有集合**随机指派**（词表 989 不变），步数按映射数同步放大 | N=40 @ 4500 步：开专家 16% / 清零 9% | **对**：记忆量涨、共享通路不涨。但 32 题留出集分辨不出这个差 |
| 步数不随 N 放大 | 900 步下 N=40 每条映射只见 9 次，全部塌掉 | **错**：把"任务更难"和"训练更少"混成一件事 |

另外两个坑不在表里，但同样致命：

- **留出集只有 32 题时，5 对 vs 3 对的差异完全是噪声。** 所以扩任务时留出集同步放大
  （每 5 条留 1 条：N=40 → 128 题，N=160 → 512 题），gap 必须带 95% 置信区间一起报。
  不同 N 之间的准确率不可比（留出集不同），只有同一 N 下的 gap 可比。
- **同配置、同 SEED 两次运行，N=10 的 gap 一次 +9pp、一次 0pp。** 这说明当前训练配方
  **不保证**产生专家知识。所以 R3 的探针必须每次训练后都跑；任何单次运行的"专家起作用了"
  都不算证据。

### B1 的实测结论：知识住在必须常驻、MoE 动不了的那部分

三个存储位置用同一种探针（推理期把该组件输出清零）测同一个 checkpoint：

| 清零的组件 | 技能题准确率 | 差 |
|---|---|---|
| 全部开 | 56.2% | — |
| 技能专家（16 个全关） | 56.2% | **0 题变化** |
| 常识 FFN | 43.8% | −12.5pp |
| 常识 FFN + 全部专家 | 43.8% | −12.5pp |

留出只有 32 题，95% 置信半宽 ±17.6pp，所以 −12.5pp 不构成证据；**唯一确定的数字是
"0 题变化"**：关掉全部专家，三组题没有任何一题的答案改变。而两个 FFN 都关掉后仍有 43.8%
（随机猜是 10%）——**模型确实会答的那部分，住在 embedding + 注意力里**，那正是必须常驻、
路由和驻留都动不了的地方。

放大留出集（128 题）重测规模扫描，也是同一个结论：N=40、步数按映射数同步放大、答案集合固定
（词表 989 不变）之后，开专家 39.1% / 清零 41.4%，**gap = −2.3pp ± 8.7pp**——与 0 无法区分。
之前 32 题上测到的 +9pp、+6pp 都是噪声。

第二个配置（`ksr_tiny.json`，4 层、专家 rank 64）上结论更强：

| 清零的组件 | 技能题准确率 |
|---|---|
| 全部开 | 56.2% |
| 技能专家 | 56.2%（**又是 0 题变化**） |
| 常识 FFN | 3.1% |
| 两个 FFN 都关 | 0.0% |

两个配置合起来把话说全了：知识要么住在 embedding + 注意力里（第一个配置，关掉全部 FFN 仍有
43.8%），要么住在常识 FFN 里（第二个配置，只剩注意力就是 0%）。**两种情况下它都不在技能专家里，
而这两种位置都必须常驻。** 换配置不改变结论，说明这不是调参能解决的问题。

### 专家这条支柱要成立，需要两个条件同时满足

1. **知识不能住在 embedding + 注意力里。** "小词表 + 短答案的任意映射"这类任务，注意力本身就
   记得动（上面 43.8% 就是证据）。要逼出专家，知识必须是**算出来而不是查出来**的——多跳组合、
   程序性步骤、风格约束——或者词表/隐层大到注意力记不动的真实规模。
2. **专家要多到装不进显存。** 180M 时全部专家只占 151 MB / 470 MB，"按需调入"没有收益。

当前原型两个条件都不满足。所以"路由精准激活专家"在这台机器上**不是没测好，是测不出来**——
这是尺度问题，不是实现问题。实现那一半已经修好了（分段分发把 E 扫描的衰减从 2.0× 压到 1.37×）。

**因此本项目的可验证部分要分开**：知识库解耦、热更新、自我纠错、检索随规模不退化——这些已经
站得住；专家支柱改为**条件式主张**，并给出能证伪它的基准（≥512 留出项、多跳组合任务、7B 尺度）。

### B5/B7 的实测边界（必须一起读，否则会被误用）

- 180M 上全部技能专家只占 **151 MB / 470 MB** 总足迹——省显存的大头不在专家，
  而共享通路和 embedding **必须常驻**。所以"硬件要求低"的正确口径是
  **常驻 = 常识通路 + 预置热专家**，不是"总参数不用装"。
- 请求期 LRU 换入换出是**净亏**：省 28% 显存、赔 **12× 吞吐**（每步搬 62 次 × 18.9 MB 走 PCIe）。
  真实流量下容量 4 只罩住 **54%** 的选择，所以必然一直搬。
- 但按领域看是集中的（`linux→专家1 76%`、`container→专家7 69%`）→ **单领域部署成立，混流不成立**。
  设计要求：**热集按流量预置、冷栈只换入不换出**（换出只在空闲期做）。
- 这套机制只在"专家装不下"的尺度才有意义（7B 的专家占 6.1 GB / 13.7 GB）。
  7B 在当前机器上连初始化都放不下（物理内存 16 GB，fp32 要 27 GB）。

## 4. 当前状态一句话

**通过：B3（热更新零重训，89% = 上界）、B4（检索随规模不退化）、B6（复犯率 0）、
B8 大部分（证据优先率 73% → 91%，副作用 0；95% 线还没到）。**
**不通过：B1 的专家半边（两个配置上全部专家清零都是 0 题变化）、B7（效率 0.70–0.99×）。**
**测不出来：B2**——知识住在必须常驻的部分（注意力或常识 FFN），MoE 动不了它。

两句话结论：

1. **知识库这条支柱站得住，而且现在有两个硬证据**：更新不需要梯度、不需要重训、跨重启有效、
   错了能改且不再犯；以及"取到之后模型会认账"——认账是训练出来的（`KSR_CONFLICT`），
   它把同一评测从 75% 抬到 92%。这是本项目目前唯一有硬证据的两条架构主张。
2. **专家这条支柱现在是条件式的**：它要求"知识算出来而不是查出来"且"专家装不进显存"，
   两个条件当前都不满足。继续做动态驻留/动态数量，是在给一个空架子装变速箱——
   先要有能跑的发动机。
